## What we are building

An iPhone app that answers one question at a glance: **"How long until my next episode, in my time zone, and where is it on?"**
It shows a live countdown on the Lock Screen and Home Screen widgets, and a scheduled release-night Live Activity in the Dynamic Island.
The app is local-first: no account, no server, no analytics. Its edge is **release times you can trust, wherever you are**: every time shows where it came from (D-17).

- Codename / repo: `next-episode`. Display name: **Airstamp** (see D-01).
- Primary user: Chime in Lagos (UTC+1, no DST). Design for viewers outside the US first.
- Full spec: `docs/SPEC.md`. Research and sources: `docs/RESEARCH.md`. Original PRD: `docs/PRD.md`.

## Stack (fixed)

- Swift 6 with strict concurrency, SwiftUI, **iOS 26.0 minimum** (scheduled Live Activities need it).
- SwiftData for the followed-shows store in the app target only.
- Widgets read a **JSON snapshot** in the App Group container, not SwiftData (D-05).
- WidgetKit and ActivityKit live in one extension target: `AirstampWidgets`.
- The project is generated by **XcodeGen** from `project.yml`. Never hand-edit `.xcodeproj` (it is git-ignored). Edit `project.yml` and run `xcodegen generate`.
- IDs and signing live in `Config/Base.xcconfig` (`BUNDLE_PREFIX`, `APP_GROUP_ID`). The Team ID goes only in the git-ignored `Config/Signing.local.xcconfig`. Never commit a Team ID. Code reads the App Group ID through `AppGroup.identifier`.
- Tests use Swift Testing (`import Testing`). There are no third-party dependencies. Any new package needs Chime's OK.

## Rules that protect correctness

1. **Store every time as a UTC `Date`.** Format only at the view layer, with `TimeZone.current`, unless the user overrides it in Settings. The one exception: a `dateOnly` drop keeps its listed `airdate` (`yyyy-MM-dd`) and is formatted from that, so it never shifts to the wrong day (D-28).
2. **Never trust a TVmaze `airstamp` when `airtime == ""`.** It is a fake noon placeholder in the channel's country zone (12:00Z for Netflix, 16:00Z or 17:00Z for Peacock and Hulu). Detect it **only** by the empty airtime, never by the hour (D-25). Resolve the time with an override or `PlatformRules` and mark it `.estimated`. If nothing matches, mark it `.dateOnly` and show no timer.
3. Every displayed time carries a `ReleaseSource`, shown as the source chip: `broadcast` ("Broadcast"), `platformRule(name)` ("Netflix rule"), `override` ("Confirmed" if confirmed, otherwise "Adjusted"), `adjusted` for an anime offset ("Adjusted"), `anilist` ("JP broadcast"), and `dateOnly` ("Date only").
4. Use `Text(timerInterval: now...drop, pauseTime: drop, countsDown: true)` or add a timeline entry at `drop`. A plain `.timer` counts *up* after zero, which is a bug here.
5. Widget timeline entries are at least 5 minutes apart. Reload policy is `.after(nextDrop)`.
6. Use `Activity.request(... start:)`, not `startDate:`, which exists only on iOS 26.0. It requires an `AlertConfiguration` and must be called while the app is in the foreground. Set `staleDate` to the drop so the view shows "Out now" without the app. Always catch `ActivityAuthorizationError`. Scheduled activities count toward an unpublished limit, so keep **at most 3 pending** (D-24).
7. Keep the Live Activity payload well under 4 KB: `dropIDs`, title, date and a short provider string only.
8. Filter AniList `isAdult == true` out of search results. Keep AniList under 30 requests a minute (its degraded limit).
9. Never bundle poster art in the repo or screenshots. The design is typographic.
10. Every TVmaze, AniList and (later) TMDB/JustWatch use is credited on the Credits screen.
11. Provider labels show the network and its country ("HBO · US"), never "On HBO" (D-20). Say "No official stream in your country" only when the rules file says so.

## Working style

- Work day by day from `docs/PLAN.md`. Pass a day's gate before starting the next.
- Write tests first for anything in `Shared/Time/`. Fixtures are recorded JSON in `AirstampTests/Fixtures/`.
- Commit after each green step with a conventional message (`feat:`, `fix:`, `test:`, `chore:`, `docs:`). **Push to GitHub after every commit** (`ChimeXXD/next-episode`, private until Day 7). Chime wants every change on GitHub.
- After UI work, build, take a simulator screenshot, and run the screen's fidelity check before calling the step done.
- Update the checkbox in `docs/PLAN.md` and the matching item in `docs/features.json` (with evidence) when a task is complete. Log each session in `PROGRESS.md`.
- Keep files under about 300 lines. Use one type per file in `Shared/`.
- Accessibility: every widget and Live Activity view gets an `accessibilityLabel` written as a full phrase built from the provider label ("Silo, in 2 days 4 hours, Apple TV"; "House of the Dragon, in 3 hours, HBO US, no official stream in your country").
