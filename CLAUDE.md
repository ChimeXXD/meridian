## What we are building

An iPhone app that answers one question at a glance: **"How long until my next episode, in my time zone, and where is it on?"**
It shows a live countdown on the Lock Screen and Home Screen widgets, and a scheduled release-night Live Activity in the Dynamic Island.
The app is local-first: no account, no server, no analytics. Its edge is **release times you can trust, wherever you are**: every time says how sure it is in plain words, and Show detail says where it came from (D-17, D-40).

- Repo: `meridian` (`ChimeXXD/meridian`; the codename was `next-episode`). Display name: **Meridian**, formerly Airstamp (D-54).
- Primary user: Chime in Lagos (UTC+1, no DST). Design for viewers outside the US first.

## Rules that protect correctness

1. **Store every time as a UTC `Date`.** Format only at the view layer, with `TimeZone.current`, unless the user overrides it in Settings. The one exception: a `dateOnly` drop keeps its listed `airdate` (`yyyy-MM-dd`) and is formatted from that, so it never shifts to the wrong day (D-28).
2. **Never trust a TVmaze `airstamp` when `airtime == ""`.** It is a fake noon placeholder in the channel's country zone (12:00Z for Netflix, 16:00Z or 17:00Z for Peacock and Hulu). Detect it **only** by the empty airtime, never by the hour (D-25). Resolve the time with an override or `PlatformRules` and mark it `.estimated`. If nothing matches, mark it `.dateOnly` and show no timer.
3. Every displayed time says how sure it is **in words**, through `ReleaseWording` (D-40), never with a colour code or dot: "Out"/"Released" for an exact time (`broadcast`, a confirmed `override`), "Expected" for an estimate (`platformRule`, an unconfirmed `override`, `adjusted`), "Airs in Japan"/"Aired in Japan" for `anilist`, and "Out Thu 19 Nov, time not announced" for `dateOnly`. Show detail explains the source in one sentence (`ReleaseWording.explanation`). The coloured `SourceChip` survives only in the pre-Night-Sky views and the widget mock-ups; it goes as each one is rebuilt on `ReleaseWording`, so never add it to new UI.
4. Use `Text(timerInterval: now...drop, countsDown: true)` **without `pauseTime`**, which freezes the timer in widgets and Live Activities (D-52). The interval alone stops at 0:00; add a timeline entry at `drop` for "Out now". A plain `.timer` counts *up* after zero, which is a bug here. In a widget or Live Activity, bound a timer with `.frame(width:)` or `.frame(maxWidth:)` rather than `.fixedSize()`: on the device a timer asks for the width of its widest value, which pushed the expanded island's whole line out of view while `ImageRenderer` renders looked fine (D-57). The Home Screen and rectangular widgets' ticking timers still use `.fixedSize(horizontal:)`; check them on the phone in a drop's last day before changing them. Renders can't show either problem, so confirm any widget or Live Activity layout change on the phone. App screens that show a countdown redraw every second (`TimelineView(.countdown)`); a slower `TimelineView` paces the ticking text and freezes it.
5. Widget timeline entries are at least 5 minutes apart. Reload policy is `.after(nextDrop)`.
6. Use `Activity.request(... start:)`, not `startDate:`, which exists only on iOS 26.0. It requires an `AlertConfiguration` and must be called while the app is in the foreground. Set `staleDate` to the drop so the view shows "Out now" without the app. Always catch `ActivityAuthorizationError`. Scheduled activities count toward an unpublished limit, so keep **at most 3 pending** (D-24).
7. Keep the Live Activity payload well under 4 KB: `dropIDs`, title, date and a short provider string only.
8. Filter AniList `isAdult == true` out of search results. Keep AniList under 30 requests a minute (its degraded limit).
9. Show artwork (posters, banners) is fetched at runtime from TVmaze or AniList and cached on the phone (D-37). Never commit artwork files to the repo; tests and committed screenshot baselines use a neutral placeholder.
10. Every TVmaze, AniList and (later) TMDB/JustWatch use is credited on the Credits screen.
11. Provider labels show the network and its country ("HBO · US"), never "On HBO" (D-20). Say "No official stream in your country" only when the rules file says so.

## Working style

- Work day by day from `docs/PLAN.md`. Pass a day's gate before starting the next.
- Write tests first for anything in `Shared/Time/`. Fixtures are recorded JSON in `MeridianTests/Fixtures/`.
- Commit after each green step with a conventional message (`feat:`, `fix:`, `test:`, `chore:`, `docs:`). **Push to GitHub after every commit** (`ChimeXXD/meridian`, private until Day 7). Chime wants every change on GitHub.
- After UI work, build, take a simulator screenshot, and run the screen's fidelity check before calling the step done.
- **The design system (`design-system/`) mirrors the app; the app is the source of truth (D-57).** A design change goes into the SwiftUI first and into the site in the same commit, whichever side Chime asked about. The render tests fail while a widget or Live Activity picture on the site differs from the app's render: after Chime approves the new render, run `scripts/sync-design-system-renders.sh`. Hand-drawn parts of the site (tokens, components, copy) are updated by hand from the Swift, never from memory.
- Update the checkbox in `docs/PLAN.md` and the matching item in `docs/features.json` (with evidence) when a task is complete. Log each session in `PROGRESS.md`.
- Keep files under about 300 lines. Use one type per file in `Shared/`.
- Accessibility: every widget and Live Activity view gets an `accessibilityLabel` written as a full phrase built from the provider label ("Silo, in 2 days 4 hours, Apple TV"; "House of the Dragon, in 3 hours, HBO US, no official stream in your country").
