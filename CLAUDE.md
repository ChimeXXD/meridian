## What we are building

An iPhone app that answers one question at a glance: **"How long until my next episode, in my time zone, and where is it on?"**
It shows a live countdown on the Lock Screen and Home Screen widgets, and a scheduled release-night Live Activity in the Dynamic Island.
The app is local-first: no account, no server, no analytics.

- Codename / repo: `next-episode`. Display name: **Airstamp** (see D-01).
- Primary user: Chime in Lagos (UTC+1, no DST). Design for viewers outside the US first.
- Full spec: `docs/SPEC.md`. Research and sources: `docs/RESEARCH.md`. Original PRD: `★ Next Episode.md`.

## Stack (fixed)

- Swift 6 with strict concurrency, SwiftUI, **iOS 26.0 minimum** (scheduled Live Activities need it).
- SwiftData for the followed-shows store in the app target only.
- Widgets read a **JSON snapshot** in the App Group container, not SwiftData (D-05).
- WidgetKit and ActivityKit live in one extension target: `AirstampWidgets`.
- The project is generated by **XcodeGen** from `project.yml`. Never hand-edit `.xcodeproj`. Edit `project.yml` and run `xcodegen generate`.
- Tests use Swift Testing (`import Testing`). There are no third-party dependencies. Any new package needs Chime's OK.

## Rules that protect correctness

1. **Store every time as a UTC `Date`.** Format only at the view layer, with `TimeZone.current`, unless the user overrides it in Settings.
2. **Never trust a TVmaze `airstamp` when `airtime == ""`.** It is a fake noon placeholder. Resolve the time with `PlatformRules` and mark it `.estimated`. If no rule matches, mark it `.dateOnly` and show no timer.
3. Every displayed time carries a `ReleaseSource` (shown as the source chip): `broadcast`, `platformRule(name)`, `anilist`, `dateOnly`.
4. Use `Text(timerInterval: now...drop, pauseTime: drop, countsDown: true)` or add a timeline entry at `drop`. A plain `.timer` counts *up* after zero, which is a bug here.
5. Widget timeline entries are at least 5 minutes apart. Reload policy is `.after(nextDrop)`.
6. `Activity.request(... start:)` requires an `AlertConfiguration` and must be called while the app is in the foreground. Always catch the error. There is no published cap on simultaneous activities.
7. Keep the Live Activity payload well under 4 KB: IDs, title, date and a short provider string only.
8. Filter AniList `isAdult == true` out of search results.
9. Never bundle poster art in the repo or screenshots. The design is typographic.
10. Every TVmaze, AniList and (later) TMDB/JustWatch use is credited on the Credits screen.

## Working style

- Work phase by phase from `docs/PLAN.md`. Finish a phase's "Done when" checks before starting the next.
- Write tests first for anything in `Shared/Time/`. Fixtures are recorded JSON in `AirstampTests/Fixtures/`.
- Commit after each green step with a conventional message (`feat:`, `fix:`, `test:`, `chore:`, `docs:`). Push at the end of each phase.
- After UI work, build and take a simulator screenshot to check it before calling the step done.
- Update the checkbox in `docs/PLAN.md` when a task is complete.
- Keep files under about 300 lines. Use one type per file in `Shared/`.
- Accessibility: every widget and Live Activity view gets an `accessibilityLabel` written as a full phrase ("Silo, in 2 days 4 hours, on Apple TV").
