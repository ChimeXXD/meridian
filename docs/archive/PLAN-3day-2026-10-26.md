# 3-Day Build Plan

There are four phases: a short Day 0 setup tonight, then three build days. Each phase lists **what Chime does** (things only a human can do: accounts, devices, taste calls) and **what Claude CLI does**, followed by a prompt you can paste into Claude CLI and a "Done when" gate.

Claude CLI ticks the checkboxes as it goes. If a day overruns, cut from the bottom of that day and move it to the Backlog. Don't push Day 3 polish out to make room.

```
Day 0  Setup (~1–2 h)        accounts, tools, repo, empty app + widget target builds
Day 1  Data + time core      TVmaze/AniList clients, TimeResolver + tests, search/follow, Upcoming list
Day 2  System surfaces       snapshot, 5 widget families, scheduled Live Activity, debug fake drops
Day 3  Refresh, polish, ship background refresh + delay, credits, a11y, CI, README, TestFlight, video
```

---

## Day 0 — Setup (tonight, about 1–2 hours)

### Chime does
- [ ] Install the latest Xcode (26.3+ or 27) and open it once. Install an iOS 26+ simulator runtime (`xcodebuild -downloadPlatform iOS`).
- [ ] Decide on the Apple Developer Program ($99/yr) and enrol now if yes (D-16). Enrolment can take up to 48 hours. Free provisioning works for simulator work, and for a device only with 7-day expiry.
- [ ] `brew install xcodegen gh`, then run `gh auth login` and sign in to your GitHub account.
- [ ] Connect the build tools to Claude CLI:
  ```bash
  claude mcp add XcodeBuildMCP -- npx -y xcodebuildmcp@latest mcp
  # optional, Xcode 26.3+: Xcode > Settings > Intelligence > "Allow external agents to use Xcode tools"
  claude mcp add --transport stdio xcode -- xcrun mcpbridge
  claude mcp list
  ```
- [ ] Choose a bundle ID prefix (e.g. `dev.chime`) and an App Group (`group.dev.chime.meridian`). Note your Team ID if you have one.
- [ ] `cd` into the Next Episode folder and start `claude`.

### Claude CLI does
- [ ] Reads `CLAUDE.md` and the `docs/` files.
- [ ] Runs `git init`, adds `.gitignore` (Xcode, DerivedData, .DS_Store, xcuserdata), and moves the PRD to `docs/PRD.md` with `git mv`.
- [ ] Writes `project.yml` with these targets: `Meridian` (iOS 26 app), `MeridianWidgets` (widget extension with `NSSupportsLiveActivities = YES` in the app Info.plist), and `MeridianTests`. Sets up the shared `Shared/` sources, the App Group entitlement on both targets, and `DISPLAY_NAME = Meridian`.
- [ ] Builds a placeholder app screen and a placeholder `systemSmall` widget, then builds and screenshots in the simulator.
- [ ] Adds `LICENSE` (MIT) and makes the first commit.
- [ ] Creates the GitHub repo and pushes: `gh repo create next-episode --public --source=. --remote=origin --push --description "Release-night countdowns for TV and anime, in your time zone. iOS widgets + Live Activities."`

**Prompt**
> Read CLAUDE.md and everything in docs/. We're doing Day 0 from docs/PLAN.md. My bundle prefix is `<dev.chime>`, my App Group is `<group.dev.chime.meridian>`, and my team ID is `<XXXX or none>`. Set up git, project.yml with the app, widget extension and test targets, the Shared folder and App Group, and placeholder screens. Build and screenshot in the simulator, commit, then create the public GitHub repo `next-episode` with gh and push. Tick the Day 0 boxes in PLAN.md.

**Done when:** `xcodebuild build` passes, the placeholder widget shows in the simulator, and the repo is live on GitHub.

## Day 1 — Data and time core (the part that must be right)

### Chime does
- [ ] Morning: confirm the platform rules table in `docs/SPEC.md` §3 matches what you see in real life (Apple TV at 02:00 Lagos and so on).
- [ ] Afternoon: follow 6–8 real shows in the simulator, including at least 2 that are airing *now* (pick from TVmaze's `/schedule/web` this week and the current AniList season), and check the times against what you know.
- [ ] Judge the Upcoming list. Does it answer "how long, when, where" in one glance?

### Claude CLI does
- [ ] Models in `Shared/Models` (`Drop`, `DropSnapshot`, `Confidence`, `ReleaseSource`) per SPEC §2.
- [ ] Records fixtures: TVmaze search and show+embed for Silo, House of the Dragon, FROM, Widow's Bay, one Netflix show and one Prime show, plus AniList for 2 currently airing anime.
- [ ] `TVmazeClient` and `AniListClient` as actors with backoff and a 6-hour cache, plus parser tests against the fixtures.
- [ ] `PlatformRules` and `TimeResolver`, written tests-first: the full zone × DST matrix from SPEC §3, and placeholder airstamps never shown as exact.
- [ ] SwiftData `FollowedShow`, a Search screen (TV/Anime segments with result disambiguation), and follow/unfollow.
- [ ] Upcoming screen: sections, big countdown, source chip, "On <provider>", `dateOnly` rows, and the "Nothing new" empty state that names the next real date.
- [ ] Show detail with the Live Activity toggle (stored only for now) and the anime offset.
- [ ] Commit per step, then push at the end of the day.

**Prompts (run them one after another)**
> Day 1, step 1: implement the Shared models and record real API fixtures as listed in PLAN.md Day 1. Then write the TVmaze and AniList clients with parser tests against the fixtures. Run the tests.

> Day 1, step 2: tests first, implement PlatformRules and TimeResolver per SPEC §3, including the zone/DST matrix and the placeholder-airstamp test. Show me the test output.

> Day 1, step 3: build Search, follow, Upcoming and Show detail per SPEC §1. Build, run in the simulator, follow Silo and two currently airing shows, and screenshot the Upcoming screen.

**Done when:** all tests pass, the Upcoming screen shows correct Lagos times with source chips for the shows you follow, and an ended or unscheduled show shows the right empty state.

## Day 2 — System surfaces (the hero)

### Chime does
- [ ] Morning: sketch or approve the widget type style. Pick one of 3 numeral treatments Claude CLI renders as SwiftUI previews.
- [ ] Install on your **real iPhone** (you need the paid or free signing from Day 0). Add the Lock Screen widgets yourself.
- [ ] Use Debug → "Live Activity for fake drop in 3 min" and watch the Dynamic Island. Note anything that feels wrong.

### Claude CLI does
- [ ] `SnapshotStore`: writes `DropSnapshot` JSON to the App Group after every change, then reloads widget timelines.
- [ ] Timeline provider per SPEC §5 (entries 5+ minutes apart, an "Out now" entry at the drop, `.after(nextDrop)`).
- [ ] Widget views for `accessoryInline`, `accessoryCircular`, `accessoryRectangular`, `systemSmall` and `systemMedium`, with previews in light, dark, tinted/accented and Always-On. Uses `Text(timerInterval:pauseTime:)` so the timer never counts up.
- [ ] `DropActivityAttributes`, plus Live Activity views: compact, minimal, expanded, and Lock Screen under 160 pt.
- [ ] `ActivityScheduler` per SPEC §6: scheduled start, `AlertConfiguration`, merging same-night drops, and caught errors.
- [ ] The Debug menu per SPEC §7.
- [ ] VoiceOver labels on every widget and activity view.

**Prompts**
> Day 2, step 1: build SnapshotStore, the timeline provider and all 5 widget families per SPEC §5. Give me 3 numeral style options as SwiftUI previews and screenshot them.

> Day 2, step 2: (after I pick a style) apply it. Then build the Live Activity per SPEC §6, ActivityScheduler and the Debug menu from SPEC §7. Test the fake-drop flow in the simulator and screenshot the Dynamic Island states.

**Done when:** on your iPhone, the Lock Screen widget counts down to a fake drop and flips to "Out now", a scheduled Live Activity appears at the lead time with an alert, and the Dynamic Island shows the timer.

## Day 3 — Refresh, polish, ship

### Chime does
- [ ] Morning: a 15-minute walkthrough. List up to 10 polish issues for Claude CLI.
- [ ] Record the 30-second portfolio video: Lock Screen countdown → Live Activity start → Dynamic Island → "Out now". Use the Debug fake drop.
- [ ] If you're enrolled in the paid program: create the app in App Store Connect and upload to TestFlight (Claude CLI can prepare the archive steps).
- [ ] Post the repo link, and decide on the final name (O-3).

### Claude CLI does
- [ ] `RefreshService` with `BGAppRefreshTask` (about every 6 hours) plus a refresh on scene-active. Diffs drops, sets `previousDate`, shows a "Delayed" badge, and reschedules activities.
- [ ] A Drop Day treatment: when a show releases a whole season at once, show "8 episodes · 7 h 20 m".
- [ ] Credits screen (TVmaze CC BY-SA with links, AniList), a no-data-collected statement, and `PRIVACY.md`.
- [ ] Onboarding (3 cards) and a Settings screen (time zone override, lead time).
- [ ] Accessibility pass: Dynamic Type up to AX5 in the app, Reduce Motion, and no colour-only cues.
- [ ] Fixes Chime's polish list.
- [ ] GitHub Actions workflow: build and run tests on `macos-latest` for each push.
- [ ] README: pitch, screenshots, an architecture diagram (Mermaid), the time-rules table, the data credits, and how to run.
- [ ] Tags `v0.1.0` and pushes.

**Prompts**
> Day 3, step 1: implement RefreshService with BGAppRefreshTask and delay detection, the Drop Day treatment, Credits, Onboarding and Settings. Add tests for delay detection.

> Day 3, step 2: here is my polish list: <paste>. Fix it, then do the accessibility pass from CLAUDE.md.

> Day 3, step 3: add the GitHub Actions CI, write the README with a Mermaid architecture diagram and screenshots, add PRIVACY.md, tag v0.1.0 and push.

**Done when:** CI is green, the README is complete, `v0.1.0` is tagged, the video is recorded, and (if enrolled) the TestFlight build is uploaded.

7. Launch: Reddit and X scan (20 quotes), 5 interviews outside the US, posts to r/iOSapps, r/anime and TV Time switchers. Decide on a Plus tier only after the TMDB licence.
