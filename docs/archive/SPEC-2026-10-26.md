# Spec — Airstamp MVP

## 1. Core question and screens

Airstamp answers one question: "How long until my next episode, here, and where is it on?"

| Screen | Purpose | Key content |
| --- | --- | --- |
| Onboarding (3 cards) | Explain, then follow the first shows | Shows your time zone ("Times shown for Lagos, UTC+1"), a button to follow shows, a prompt to add a widget |
| Search | Find TV (TVmaze) and anime (AniList) | Segmented TV / Anime; each result shows year, network and status; never auto-pick the first result (searching "Euphoria" also returns an Israeli show) |
| Upcoming (home) | Every followed show sorted by time to drop | Big countdown, show name, `S1E4`, local day and time, source chip, "On HBO"; sections: Tonight · This week · Later · Date only · Nothing scheduled |
| Show detail | One show | Next drop, the last 3 aired episodes, a Live Activity toggle, an anime offset field, an unfollow button |
| Settings | Preferences | Time zone override, Live Activity lead time (30 min to 6 h), credits, Debug menu (Debug builds only) |
| Credits | Licences | TVmaze (CC BY-SA, with link), AniList, and a "no data collected" statement |

**Empty state ("Nothing new this week")** names the next real date, e.g. "Silo returns 9 Jul 2027". If no followed show has anything scheduled, it says "Nothing scheduled for your shows yet. We check every 6 hours."

## 2. Data model

```swift
// Shared/Models
enum Catalog: String, Codable { case tvmaze, anilist }
enum Confidence: String, Codable { case exact, estimated, dateOnly }
enum ReleaseSource: Codable, Hashable {
    case broadcast(network: String)        // TVmaze airtime + network timezone
    case platformRule(String)              // e.g. "Netflix: midnight PT"
    case anilist                           // AniList airingAt (JP broadcast)
    case dateOnly
}
struct Drop: Codable, Hashable, Identifiable {
    var id: String                // "\(catalog):\(showID):\(episodeID)"
    var showID: String
    var showName: String
    var season: Int?; var number: Int?
    var episodeTitle: String?     // hide in widgets (spoiler-safe)
    var date: Date                // UTC instant (for dateOnly: start of the local day)
    var confidence: Confidence
    var source: ReleaseSource
    var provider: String?         // "HBO", "Apple TV", "Netflix", "Crunchyroll"
    var previousDate: Date?       // set when a refresh moved the time
}
struct DropSnapshot: Codable { var generatedAt: Date; var drops: [Drop]; var nextReturn: Drop? }
```

SwiftData (app only): a `FollowedShow` holds `catalog`, `externalID`, `name`, `provider`, `liveActivityEnabled`, `animeOffsetMinutes`, `addedAt`, plus cached `[Drop]` for the next 30 days.

## 3. Time resolution (the heart of the app)

`TimeResolver.resolve(episode:show:) -> (Date, Confidence, ReleaseSource)` works through these steps in order:

1. **AniList:** `airingAt` (Unix time) + the show's `animeOffsetMinutes` → `exact` if the offset is 0 (labelled "JP broadcast"), otherwise `estimated`.
2. **TVmaze with `airtime != ""` and a network timezone:** trust `airstamp` → `exact`, `broadcast(network)`.
3. **TVmaze with `airtime == ""`:** look up `PlatformRules` by `webChannel.name` or `network.name` → `estimated`.
4. Otherwise → `dateOnly` (show "Wed 29 Apr · time not announced").

`PlatformRules` v1 (each rule needs 2 real examples in the fixtures before shipping):

| Platform (TVmaze name) | Rule | Lagos time | Source |
| --- | --- | --- | --- |
| Netflix | 00:00 America/Los_Angeles on airdate | 08:00 (09:00 in PST months) | whats-on-netflix |
| Prime Video / Amazon | 00:00 America/Los_Angeles on airdate | 08:00 / 09:00 | TechRadar (The Boys S5) |
| Apple TV (was Apple TV+) | 21:00 America/New_York on airdate − 1 day | 02:00 / 03:00 on airdate | TVLine (Ted Lasso S4) |
| Disney+ | 18:00 America/Los_Angeles (check O-2) | 02:00 next day | SuperHeroHype |
| HBO / HBO Max | Usually has an airtime (21:00 ET), so step 2 applies | 02:00 / 03:00 | TVmaze |
| Anything else | dateOnly | — | — |

Lagos has no DST, so the Lagos clock time shifts by an hour when the US changes clocks. Tests must cover this.

**Required tests (Swift Testing):**
- Each rule × {US summer, US winter} × {Africa/Lagos, Europe/London, Asia/Kolkata, Asia/Tokyo, America/New_York, Australia/Sydney}.
- The US DST changeover weeks (8 Mar 2026, 1 Nov 2026, 14 Mar 2027), and an anime case where JST stays fixed while the US time moves.
- A placeholder airstamp (`12:00:00+00:00` with an empty airtime) is never shown as `exact`.
- Delay detection: when the same episode id gets a later date, `previousDate` is set and the drop is shown as "Delayed".

## 4. Networking

| API | Endpoints | Limits | Notes |
| --- | --- | --- | --- |
| TVmaze `https://api.tvmaze.com` | `/search/shows?q=`, `/shows/{id}?embed[]=nextepisode&embed[]=previousepisode`, `/shows/{id}/episodes` | 20 calls / 10 s per IP; HTTP 429 → back off | `_embedded.nextepisode` is missing when there is none. Fields used: `airdate, airtime, airstamp, season, number, name`; show `network{name,country{timezone}}`, `webChannel{name}`, `status` |
| AniList `https://graphql.anilist.co` (POST) | `Page{media(search:, type: ANIME, isAdult:false){id title{romaji english} status nextAiringEpisode{airingAt episode} airingSchedule(notYetAired:true, perPage:10){nodes{airingAt episode}}}}` | 90/min (30 when degraded); 429 with `Retry-After` | Filter `isAdult` |

- Both clients are `actor`s with an exponential backoff on 429 (honour `Retry-After`) and a 6-hour on-disk cache.
- Record real responses into `AirstampTests/Fixtures/` and build the parsers against those.

## 5. Widgets (`AirstampWidgets`)

| Family | Content |
| --- | --- |
| `accessoryInline` | `Silo · 2d 4h` |
| `accessoryCircular` | Big numeral ("2d" / "4h" / "38m") with a progress ring over the last 7 days |
| `accessoryRectangular` | Show name, countdown, `Wed 02:00 · Apple TV` |
| `systemSmall` | Huge typographic countdown, the show name small, the source chip |
| `systemMedium` | The next 3 drops as rows |

- The provider reads `DropSnapshot` from the App Group. Timeline: one entry now, one at each of the next 5 drops (and drop + 1 h for "Out now → next"), all at least 5 minutes apart. Reload policy is `.after(nextDrop)`.
- At the drop time the widget shows "Out now on HBO" for 1 hour, then moves to the next drop.
- A `dateOnly` drop shows "Wed 29 Apr" with no timer.
- Rendering: `.containerBackground(for: .widget)`; check `widgetRenderingMode` for accented/tinted; `isLuminanceReduced` for Always-On.
- The app calls `WidgetCenter.shared.reloadAllTimelines()` after every snapshot write.

## 6. Live Activity

```swift
struct DropActivityAttributes: ActivityAttributes {
    struct ContentState: Codable, Hashable { var phase: Phase; var dropDate: Date; var delayedFrom: Date? }
    enum Phase: String, Codable { case upcoming, outNow }
    var showName: String; var episodeLabel: String; var provider: String?
}
```

- **Compact leading:** a monogram or a small icon. **Compact trailing:** a timer. **Minimal:** the timer. **Expanded:** show name, `S2E5`, a big countdown, "On HBO · 02:00".
- **Lock Screen view:** at most 160 pt tall. iOS 27 StandBy scales it 200%, so test with `showsWidgetContainerBackground`.
- **Scheduling:** `ActivityScheduler` runs on scene-active. For opted-in drops in the next 7 days with confidence ≠ `dateOnly`, it calls `Activity.request(attributes:content:pushType:nil, style:.standard, alertConfiguration:..., start: drop − leadTime)`. Check the label in Xcode autocomplete, as Apple's docs show both `start:` and `startDate:`. It skips drops that already have a pending activity, merges same-night drops, and catches and logs errors.
- **At the drop:** the app updates the activity to `.outNow` if it is running. If it isn't, the timer view reads `dropDate` and flips by itself (use `Text(timerInterval:pauseTime:)` and a date check). End with `.after(drop + 1h)`.
- **Alert copy:** "Silo starts in 2 hours · 02:00 on Apple TV".

## 7. Debug menu (Debug builds only)

- "Fake drop in 2 / 10 / 60 minutes" injects a fake followed show and drop and rewrites the snapshot.
- "Schedule Live Activity for fake drop in 3 minutes (lead 1 min)".
- "Dump snapshot JSON" and "Simulate delay +1h".
