# Meridian: phased plan from start to launch

Rewritten 29 Oct 2026. It replaces the 3-day plan, which is archived in `archive/PLAN-3day-2026-10-26.md`. The research behind each change is in `RESEARCH.md` (29 Oct update), and the decisions are D-17 to D-31 in `DECISIONS.md`.

Updated the same day: **no Figma.** The UI is vibe-coded straight into SwiftUI, with references as the reference library (D-31).

Each phase lists its goal, **what Chime does** (accounts, devices, taste calls, people), **what Claude CLI does**, a prompt to paste, and an **exit gate**. Don't start the next phase until the gate passes. The exceptions are the tracks marked as running in parallel.

## Why the plan changed

1. **A Live Activity countdown is no longer special.** Up Next, which is free, and Rexy and Kiroku, which are paid, already ship one. Our edge is **times you can trust outside the US**: every time shows its source, and the app never shows a placeholder time as if it were real. No competitor shows where a time came from. Reviews of Trakt, Sofa and Next Episode complain about times being 1–2 hours off, "12am" placeholders, and US times shown to people abroad.
2. **Accuracy needs a way to fix rules after launch.** Release rules have exceptions. Netflix event drops come out at 17:00 PT. Prime moved the *Fallout* premiere forward. Disney+ has no single rule. So platform rules and per-episode overrides move into a JSON file in the public repo. The app bundles a copy and fetches updates, so we can fix a wrong time without an App Review (D-18).
3. **AniList's terms may forbid tracker apps.** Phase 1 asks AniList for permission, and the fallback is TVmaze's anime coverage (D-19).
4. **"Where to watch" must be honest in Nigeria.** HBO left Showmax in January 2026, and Showmax closed on 30 April 2026. "On HBO" is wrong for a Lagos viewer. The label shows the origin network and country until region data arrives (D-20).
5. **UI direction comes from references, then goes straight into code.** There is no Figma step. Claude pulls design references for each surface, writes a short UI brief, and builds the screens in SwiftUI. Chime approves each screen from simulator screenshots, and every approved screenshot becomes the baseline that later changes are checked against (D-31).
6. **Three days was never realistic for a shippable app.** The real target is the App Store, with a 14-day beta to prove accuracy. The new schedule puts launch at about 7 weeks of calendar time, roughly 17 focused days.

## Phase 2: UI direction, references to SwiftUI (Wed 4 – Thu 5 Nov)

**Goal:** a clear, referenced direction for every screen, captured as a written brief and as real SwiftUI tokens and components, so Phase 4 builds screens instead of guessing. There is no Figma (D-31). The typographic, poster-free direction (D-13) stays.

### 2a. Gather references in references (half a day)
Claude runs one reference search per surface (iOS), following the `references:search` skill rules, and saves the strongest 3–5 per surface to the `Meridian references` collection with references `save_content`. Each reference gets a one-line note in `docs/design/REFERENCES.md` on **which pattern we take and why**, or why it's rejected. The seed pass is already there.

| Surface | references query (one target per query) |
| --- | --- |
| Upcoming (home) | "upcoming schedule grouped by day with times", "TV show tracker upcoming episodes list with countdown" |
| Time-zone honesty | "schedule with my time and local time toggle" (seed: Formula 1's "My time / Track time") |
| Search | "search results with year and network to tell apart same-name titles" |
| Show detail | "TV show detail with next episode and episode list" |
| Onboarding | "onboarding prompting to add a home screen widget" |
| Empty states | "schedule with nothing upcoming" |
| Settings | "settings screen with time zone picker" |
| Lock Screen Live Activity | "lock screen live activity with countdown timer" (seeds: Apple Fitness, Once, Duolingo) |
| Dynamic Island | "dynamic island compact countdown" |
| Widgets | "lock screen widgets countdown", "home screen widget countdown large numeral" |
| Flows (`search_flows`) | "follow a show from search", "enable live activity from settings" |

### 2b. Write the UI brief (half a day)
`docs/design/UI-BRIEF.md` has one section per screen and surface:
- the job it does, in one line
- the design references it borrows from, with links
- the elements, in reading order, each with a test ID
- the exact copy, taken from SPEC and never retyped from memory
- every state: loading, empty ("Silo returns 9 Jul 2027"), date only, estimated, delayed, offline, Live Activities off, no official stream in your country, and AX5

This brief becomes the `fidelity/inventory/<screen>.json` that Phase 4 checks against.

### 2c. Style in code (half a day)
- [ ] `Shared/Design/Tokens.swift`: colour (light, dark and the tinted/accented widget mode), spacing, radii, and a type scale with SF Pro Rounded or SF Compact numerals using **tabular figures**, plus SF Pro for text.
- [ ] Components with `#Preview`s: `SourceChip` (`Broadcast`, `Netflix rule`, `Confirmed`, `Adjusted`, `JP broadcast`, `Date only`), `CountdownText`, `DropRow`, `ProviderLabelView` (`HBO · US`), `SectionHeader`.

### 2d. Numeral studies as SwiftUI previews (half a day)
- [ ] 3 numeral treatments across `accessoryInline`, `accessoryCircular`, `accessoryRectangular`, `systemSmall` and `systemMedium`, plus the Live Activity Lock Screen view, each in light, dark, tinted and Always-On. Render them to PNGs in `docs/design/studies/` and show Chime a side-by-side. **Chime picks one** and the choice goes in `DECISIONS.md`.

**Chime does:** react to the reference board (anything you love or hate?), and pick the numeral style.
**Claude CLI does:** the reference searches and saves, the UI brief, the tokens and components, and the numeral studies.

**Prompts**

## Phase 9: Grow (January 2027 onward, in this order)

**Goal:** keep times correct through each clock change, then add the next most-wanted feature, one release at a time.
**Chime does:** prioritise, recruit interviewees, and decide on pricing. **Claude CLI does:** build each item through the same build → verify → beta loop.
**Gate for each item:** its SPEC criteria pass, and the 20-drop accuracy audit for that release is logged.

1. **Run the DST regression in the weeks of 14 and 28 Mar 2027** (US, then EU). Re-run the accuracy audit on 20 drops.
2. **Region-aware "where to watch"** via TMDB watch providers (non-commercial licence, with JustWatch credit). Nigeria first, and show "No official stream in Nigeria" when that's the truth.
3. **Simulcast translator:** show the JP broadcast time and the platform stream time side by side.
4. **StandBy layout and a `systemExtraLargePortrait` widget** (iOS 27).
5. **Calendar export** (EventKit write-only), a Sunday digest notification, and **Drop Day** for whole-season releases ("8 episodes · 7 h 20 m"). Drop Day needs episode runtimes, which v1 doesn't model (D-29).
6. **Importers:** TV Time GDPR export (`tracking-prod-records-v2.csv`, TVDB IDs mapped through TVmaze `lookup/shows?thetvdb=`) and Trakt JSON export. These are lower priority now because most TV Time users have already moved elsewhere.
7. **Monetisation decision** at around 1,000 monthly users (from App Store Connect analytics, which users opt into): tip jar first, then possibly Plus at about $9.99/yr or $24.99 lifetime. A countdown alone won't sell, because free apps have one. Plus needs a TMDB commercial licence first.
